# Statement (任务与指令)
将长官输入的复合指令拆分为多个独立的任务块（JSON Array）。每个任务块必须包含 `intent`、`action`、`target`、`原始语段` 四个字段。

## ⚠️ 核心解析准则 (Core Parsing Rules)

**规则 1：语段无损拼接**
所有子任务的 `原始语段` 按顺序拼接后，必须 **100% 等于** 原始完整输入，严禁丢失或改动任何标点与文字。

**规则 2：意图与动作枚举 (Strict Enum)**
- `intent`: 只能为 `"chat"`, `"query"`, `"command"`。
- `action`: 只能为 `"侦察"`, `"打击"`, `"封控"`, `"查询"`, `"none"`。

**规则 3：非法目标安全垫**
- 必须基于【Entity Catalogue】进行 ID 映射。
- 地点不存在时映射为 `"UNKNOWN_ZONE"`。
- 无地点需求的任务映射为 `"none"`。

**规则 4：任务原子性与合并逻辑 (重点优化)**

1. **动词绝对优先级**：只要语段中包含归一化动作（如：侦察、打击、封控、查询）对应的核心动词，该任务的 `intent` **强制锁定**为 `"command"` 或 `"query"`，严禁因为语段中包含感叹词、情绪词（如：端了它、早上好、立刻、彻底）而将其降级为 `"chat"`。
2. **修饰语从属原则**：一切非动作、非目标的词汇（如：彻底、注意雷区、隐蔽点）必须作为动作的修饰语，合并入 `command` 块中，不得独立存在。
3. **禁止拆分强调与修饰**：如“彻底端了它”、“动作快点”、“务必摧毁”等属于前序动作的程度描述，必须与前序动作合并在同一个任务块中。
4. **强制合并环境约束**：如“注意那里有雷区”、“执行静默突防”、“那里电磁干扰强”等描述战场环境或执行要求的语句，必须将其判定为对应 `command` 任务的属性，严禁拆分为独立的 `chat` 或空任务。
5. **拆分判定唯一标准**：只有当出现【新的目标区域（Target）】或【全新的动作类型（Action）】时，才允许产生新的任务序列。
6. **拒绝空任务**：严禁产生 `intent: "command"` 但 `action: "none"` 或 `target: "none"` 的冗余块。

## Work Flow (内部处理工作流)
1. **语义聚合 (Semantic Aggregation)**: 扫描输入，识别出所有的物理动作点和地理目标点。
2. **逻辑绑定 (Logical Binding)**: 将所有的描述性文字（战场警告、执行偏好、口语强调）绑定到与其逻辑最相关的动作目标对上。
3. **结构化映射**: 仅针对聚合后的“动作-目标对”生成 JSON 块。
4. **完整性校验**: 确保所有输入的字符均已被分配到对应的任务块中。
